# Version 16.1.0 Release Notes

## Highlights

- **No ERPNext required.** Paystack is now a Frappe Payments gateway for any app: install it with just Frappe and Payments. LMS, Payments Web Forms and Education work out of the box; ERPNext features activate automatically when ERPNext is installed.
- **One codebase for Frappe version-15, version-16 and develop.**
- **Safer checkout.** Every transaction is initialised on the server (inline popup via `resumeTransaction`, or hosted page) and verified with Paystack before anything is trusted. Unsupported currencies are refused instead of being charged as NGN; XOF and Paystack's minimum amounts are enforced.
- **Completion does not depend on the webhook alone.** The payer's return, the webhook, a 10-minute sweep and the desk "Verify with Paystack" action all complete the payment the same way.
- **Your application is told exactly once, as the payer.** Callbacks run as the user who started the payment, even when a webhook or an administrator completes it, so LMS enrols the learner, never Guest or the administrator. Failing callbacks are retried and can be resolved from the desk.
- **Refunds follow Paystack.** Pending refunds hold the balance; refunds complete when Paystack reports them processed (webhook or hourly poll); dashboard refunds are recorded.

## ERPNext

- Everything from 15.x is preserved through the ERPNext adapter: Payment Requests and Webshop, Payment Entries with retries, POS, Dunning, subscriptions, credit-note refunds with reversal entries, settlement journals, company routing, saved cards and the customer portal.
- Payments now show a separate **Booking Status**. Existing records are migrated (`Processed` → Paid/booking Pending, `Completed` → Paid/booking Booked).

## Upgrading

Run `bench migrate`. Webhook URLs, checkout links, the Payment Gateway name and the 15.x whitelisted methods keep working. See the README for details.
